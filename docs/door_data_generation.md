## 已确认需求

- 用于微调 GR00T N1.7；无需人类遥操数据，不采用 RL。
- 机械臂基座水平半径 0.59 m，高度 0.63 m，门前法线两侧 ±30° 采样。
- 圆把手逆时针旋转 45° 解锁；没有下压步骤。
- 握住把手先拉出门缝，松开后重新夹住门侧沿，再继续拉开。
- 实机策略输入是一台眼在手上的摄像头，安装于 joint6 附近，能看到两个夹爪，
  相对夹爪朝前方向向下倾斜 30°，随 joint6 一起转动（用户已确认）。
  在 URDF/USD 中刚性安装应依附 link6，不依附关节 prim，也不随单侧手指平移。
- 基座朝向、把手实测高度、精确相机内外参及最终
  开门角度仍需确认。现有场景的临时默认值不应称为实测标定。

## 分步仿真示教与专家目标

当前试采由操作者（可由助手通过工具承担）查看腕部图像、关节、接触和门状态后，
逐段发送短动作。`scripts/door_teach_session.py` 在指令之间暂停物理时钟，
记录时间不包含工具调用等待。以下表格是完整专家的验收目标，不代表均已跑通。

| 阶段 | 控制行为 | 完成条件 |
| --- | --- | --- |
| approach_knob | cuMotion 到预抓位，低速接近圆把手 | 抓握位姿可达且无非预期碰撞 |
| grasp_knob | 双指夹住圆把手 | 双侧接触、夹持稳定 |
| unlock_knob | 围绕把手轴逆时针旋转 45° | 把手角度及锁舌回缩量达标 |
| crack_door | 保持解锁握姿，沿铰链运动拉出门缝 | 锁舌越过扣板、门缝足够换抓 |
| release_knob | 松开并退出 | 夹爪脱离；门没有关闭或重新锁住 |
| approach_edge | 移至门侧沿预抓位 | 两指能分别到达门板两侧 |
| grasp_edge | 夹住侧沿 | 夹持稳定，指尖不顶在侧沿端面 |
| pull_edge | 按门铰链运动更新侧沿抓握目标 | 达到设定门角度且没有失去抓握 |
| finish | 按任务定义保持或释放 | 终止条件成立 |

逆时针暂按机器人位于门前、面对圆把手的视角定义。USD 关节正角度不一定
对应这个方向：现有门资产 handle_joint 的轴为 Y，前侧在 −Y，必须核对
关节局部坐标和锁舌 mimic 的符号，不能仅凭 upperLimit=45 判定正确。
夹爪需绕圆把手实际转轴运动，不能假定给 joint6 加 45° 就等价。

换抓门缝由门厚、手指厚度、夹爪开度和进出路径的碰撞共同决定。
不能以一个没有验证的固定门角度代替换抓可行性。记录松开后门角变化；
如果回关导致重锁或挤住手指，应作为失败，而不是锁住门的仿真状态强行通过。

专家可读仿真真值（门角、把手角、锁舌、接触）计算动作与阶段条件。
接触阶段使用连续 IK 和受限的低速跟踪；cuMotion 用于自由空间接近/转移。
只向机器人发送动作，不能直接驱动门关节来伪造成功。
先完成固定中点全流程，再逐步扩大到 ±30° 和物理/视觉随机化。
稳定的专家本身即可批量生成数据；Mimic 增广是之后的可选步骤。

## 单腕部视觉

现有 `config/vla_scene.yaml` 的 D455 挂在 `/R5a/link6/rsd455/...`，
光轴相对 link6 为 `[0.8660253514, 0, -0.5000000908]`，对应相对 +X
向 −Z 倾斜约 30°。这是现有资产参数，不代表已与实机完成标定。

静态预览脚本只渲染外部总览；示教会话另在 link6 上建立本地腕部相机并实际渲染，
不加载远程传感器 payload。已记录接近、抓握、转动、门缝、换抓和拉门的腕部画面。
侧抓时部分手指会被门板遮挡，仍需用户审核可见性和标定参数。
腕部画面随手腕旋转属于真实观测，不应人为稳定为世界坐标画面。
外部相机可以用于调试录像，但不进入只部署腕部相机的策略输入。

## GR00T N1.7 数据输出

最终训练产物采用 GR00T LeRobot v2，沿用项目固定版本的 v2.1 兼容目标，
含 `meta/modality.json`。不能仅安装最新 LeRobot 并默认写 v3 后声称兼容。

官方依据（本次已核对）：

- https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/data_preparation.md
- https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/data_config.md

每个采样时刻保存：

- `observation.images.wrist`：单腕部 RGB 视频。
- `observation.state`：当前 `[joint1..joint6, gripper]`，6 个弧度值和
  1 个主动夹爪关节米制位置，沿用当前项目绝对值约定。
- `action`：将要执行的绝对 6+1 关节目标，来自最终 IK/控制器输出，
  不能用执行后的反馈状态代替。
- 时间、episode/frame 索引、任务文本映射，及 GR00T 所需元数据和统计。

默认沿用 30 Hz 采样时钟，物理子步可更高。动作与图像/状态在统一步边界
配对后才推进物理。训练动作表示及 action chunk 长度在 N1.7 modality
配置中确定，不等同于原始数据必须存增量。

完整 episode 包含解锁和换抓，不能把换抓之间的必要动作删掉。
阶段、门角、把手角、接触、失败原因、seed 另存诊断记录，不作为需要
仿真真值的模型输入。默认指令描述整个任务；逐阶段文本可用于诊断或额外
训练方案，但不能让部署依赖仅仿真中可用的阶段标签。

当前 `raw_v1_writer.py` 固定 `CAMERAS=('front','wrist')`，ROS recorder
也要求两路图像。门任务使用独立的 `door_teach_session.py` 原始记录和
`export_door_lerobot.py` 单腕部导出路径，详见 `door_lerobot_export.md`；
既有双相机采集契约保持独立。
不得复制 wrist 视频冒充 front 或填入黑图来绕过双相机校验。
可保留中间原始记录用于审计，但最终交付应直接提供可被目标 N1.7 loader
加载的 LeRobot 数据集。先用少量完整成功 episode 做加载和回放验收，再批量生成。
