## 选择：Isaac Lab Mimic / SkillGen 加现有 cuMotion

推荐采用官方 Isaac Lab Mimic 的示范片段处理与 SkillGen 的规划连接框架，
为 ARX 开门任务增加适配。SkillGen 将物体相关的技能片段与运动规划结合，
官方默认规划器是 cuRobo，并提供可扩展的规划器接口。
本项目通过接口复用已工作的 cuMotion 原生独立进程、URDF/XRDF 和障碍物导出。
生成由官方 `DataGenerator` 执行，项目适配器负责 ARX 的 seeded IK、
cuMotion 关节空间规划、动态门碰撞场景和物理验收。
依据：[官方 SkillGen 文档](https://isaac-sim.github.io/IsaacLab/main/source/overview/imitation-learning/skillgen.html)。

方案比较：

| 方案 | 作用 | 本项目取舍 |
| --- | --- | --- |
| Isaac Lab Mimic / MimicGen 路线 | 将示范分成物体相关片段，迁移到新配置并在仿真执行 | 作为动作增广基础 |
| SkillGen | 结合技能片段与运动规划，重新连接接近、退出、换抓路径 | 推荐主线，尤其适合当前换抓转移 |
| GR00T-Dreams / DreamGen | 生成机器人视频，再通过逆动力学模型提取动作 | 暂不作为 ARX 首轮路线 |
| Cosmos Transfer | 受深度、分割等条件约束的视觉变化 | 动作增广稳定后的小规模可选实验 |

DreamGen 官方仓库列出的内置 embodiment 是 Franka、GR1、SO100、RoboCasa；
其他形态需训练/适配 IDM。ARX 的单腕部相机并非现成支持项。
这是当前不优先选择它的工程原因，不是算法效果的通用排名。
依据：[DreamGen 仓库](https://github.com/NVIDIA/GR00T-Dreams)。

Cosmos Transfer 支持 RGB、深度、分割等条件下的视频生成，但它的输出仍需检查
是否改变手指、门沿、旋钮和接触关系。不能将视觉上合理的视频直接视为准确的
ARX 动作标签。依据：[Cosmos Transfer 2.5 文档](https://docs.nvidia.com/cosmos/latest/transfer2.5/index.html)。

## 动作生成方式

先固定三段主要接触技能：握旋钮并解锁、保持握持拉出门缝、高位夹边并拉门。
松开、退出和换抓属于显式阶段，段间自由空间路径由 cuMotion 重新规划。
现有 phase 用来提出子任务边界，再结合接触与关节状态检查、显式确认起止帧。
官方 SkillGen 教程要求起止标注，不能直接假定 Mimic 的自动标注选项适用于它。

把旋钮轴、门铰链和门侧沿作为参考，保留种子中的相对运动与转角进程。
每段开始依据当前门状态更新参考；不能用逐帧跟随物体的坐标变换把原本的
旋钮旋转或开门运动抵消掉。关节角随新的基座位置重新求解，不直接加随机噪声。
门是受铰链约束的 articulation，不能套用拿起方块的刚性 attach/detach 行为。
执行中只控制机器人，通过物理接触带动门，持续检查门缝、解锁与双指抓握。

每次生成均重新执行物理和渲染腕部 RGB。生成器可使用仿真真值，最终 VLA 输入
只含单腕部 RGB、机器人自身状态和任务文本；门角、接触、物体真值仅作诊断。
相机固定在 link6、向下 30°，不为绕过遮挡而随机移动挂载点。

## 分阶段验收

1. **兼容与基准**：新增最小单环境；转换/补录并显式标注种子；0° 基座位置
   零扰动回放通过完整动作、接触、视点保护和时间对齐检查。
2. **第一小批**：0°、±3°、±5° 共五个位置各做一次试生成。半径仍为 0.59 m，
   基座高度 0.63 m，朝向沿用面向把手。保留每次尝试和失败原因，输出成功片段
   的双视角回放及 seed、来源示范、采样参数、分阶段结果。五次尝试不保证五条成功。
3. **扩大几何覆盖**：逐步覆盖 ±15°、最终 ±30°；按角度区间报告成功率和失败阶段。
   失败区间先查可达性与接触姿态；必要时用现有专家补少量不同抓姿种子。
   不悄悄缩小用户要求的 60° 范围，也不承诺一条种子能覆盖全部范围。
4. **视觉增广**：先在仿真中改变灯光、背景、门板颜色/粗糙度及合理图像噪声；
   保持机器人、旋钮与门沿几何正确。稳定后再用深度/分割约束测试 Cosmos Transfer。
   同一动作的外观变体必须跟随同一训练/验证划分，避免近重复泄漏。
5. **训练接口**：通过审核的记录导出 GR00T 所需的 LeRobot v2.1 兼容结构，
   单腕部 RGB、7D 绝对关节控制目标及 `meta/modality.json`。先用固定版本的
   N1.7 官方 loader 实际加载小批数据、核对动作单位和时间对齐，再扩大数量。
   验证集预留未用于生成调参的位置/场景组合。

Mimic/SkillGen 的内部 HDF5 与最终训练用 LeRobot 是不同用途的产物，应同时保留。
GR00T 当前公开数据准备文档要求 v2 与 modality 元数据；不能默认最新 LeRobot v3
即可直接用于本项目。依据：[GR00T 数据准备](https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/data_preparation.md)。

所有阶段沿用失败拒收、相机视点检查和非指爪接触检查，同时保持对检查覆盖范围
的说明。首批单环境运行，确认资源占用后再考虑并行。首个交付是零扰动复现与
五个小范围位置的试生成结果，不是直接生成数千条数据或开始微调。

## 本地运行与当前边界

从仓库根目录运行，使用装有 Isaac Lab 的 Python；新尝试必须使用新的输出目录：

```bash
PYTHONPATH=arx_r5_isaac_sim_bringup \
  /home/lbz/miniforge3/envs/isaaclab/bin/python scripts/run_door_skillgen_batch.py \
  --output-root generated/door_skillgen/my_first_batch \
  --angles 0 -3 3 -5 5
```

先试原位时只传 `--angles 0`。每个角度下保存 `scene.usd`、`scene.json`、
`cuboids.json`、`generation.log`、`result.json`、HDF5、`wrist.mp4`、
`overview.mp4` 和各次规划的原始请求/返回值（换抓增加一次短接近规划）。
失败记录不删除、不计入训练集。
Kit 的进程返回值可能为零，即使生成失败；应读取 `result.json.success`。

本次迁移已定位并处理的差异：

- 快照原本是开门中途状态：按关节零位重建门、旋钮、锁舌的实体变换。
- 环境 reset 必须实际重置两套 articulation，不能只清空管理器缓存。
- 旋钮参考统一使用 `grasp_target`，不是相距 67 mm 的刚体原点。
- 沿用 USD 实际驱动参数：角度刚度/阻尼经 degree→radian 转换，不能直接复制
  USD 字面值到 Isaac Lab tensor API；夹爪 joint8 保持被动 mimic。
- SkillGen 每段先连接到源片段的实际入口位姿，再执行该片段的目标动作。
  第一条目标动作已经向接触面运动，不能将它误当作自由空间规划的终点。
- 门松手后仍可能运动：长转移先到入口沿门法向外侧 4 cm，临时朝向门板，
  避免保持接近关节限位的侧抓姿态后退。转移结束后只刷新一次门板参考，
  再用 cuMotion 连接新的入口。整段夹边动作使用刷新后的固定参考，不能逐帧
  追随门板而抵消原示范的拉门运动。不修改门状态、不删除碰撞体。

当前物理审计在 30 Hz 控制步后采样，仿真本身为 120 Hz。检查包括真实双指接触、
解锁、夹持拉缝、最终门角、门沿双侧法向夹持力、相机净空和非指爪接触。
这不等价于覆盖每一个 120 Hz 子步。视频与 HDF5 为动作执行前观测，30 Hz 对齐。
目前未启用视觉随机化；导出和 GR00T loader 链路已实现，但格式通过不能替代
视觉验收。以下历史结果含旧相机记录，不作为最终训练集。
